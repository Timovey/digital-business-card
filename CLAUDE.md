# CLAUDE.md

Guidance for Claude Code (and humans) working in this repository.

## What this is

Backend "digital business card": NestJS 12 + Apollo GraphQL (code-first) + Prisma 7 + PostgreSQL 17 + S3.
Read-only public API; data is owned by the seed (`prisma/seed/data/*.ts`).

## Commands

```bash
docker compose up --build              # whole stack from scratch (migrate + seed + API)
docker compose up -d postgres s3       # infra only, for local development
npm run db:setup                       # prisma migrate deploy + seed (idempotent)
npm run start:dev                      # API with watch; regenerates schema.gql
npm test                               # unit tests
npm run test:e2e                       # e2e, needs migrated + seeded DB and S3; regenerates schema.gql
npm run schema:check                   # fails if schema.gql differs from the committed one (CI runs it after e2e)
npm run lint && npm run typecheck && npm run format:check
npm run db:migrate:dev -- --name <x>   # new migration after editing schema.prisma
```

## Architecture rules

- Folders: `src/` root holds only `main.ts` and `app.module.ts`; `config/`, `graphql/` (config, context, errors,
  query limits, scalars, pipes), `infra/` (prisma, storage), `common/`, `health/`, `modules/` (features +
  `api.module.ts`). Longer design write-ups go to `docs/`.
- Feature module = `models/` (GraphQL types) + `*.resolver.ts` + `*.service.ts` + `*.loaders.ts`;
  register it in `modules/api.module.ts`, not in `AppModule`.
- **Resolvers**: GraphQL only. No Prisma, no business rules. They call services (and `*Loaders`), never rule files.
- **Services**: data access via `PrismaService` (always batch by `IN (...)`, always `orderBy`) plus thin delegation to
  business rules. No repository layer.
- **Business rules** are pure functions in their own files (`experience-period.ts`, `skill-grouping.ts`,
  `project-filter.ts`): no Prisma, no Nest; time is passed in (services take it from `Clock`). Test them without mocks.
- **Relations are resolved through DataLoader**: add a `BatchLoadFn` to the module's `*Loaders` class and call
  `loaders.get(this.xLoaders.fn).load(id)` with `@Loaders()`. Never query inside a `@ResolveField` per parent.
  Always pass the stable `*Loaders` field — an inline arrow creates a new DataLoader per call and silently brings N+1 back.
- A module adds fields to `Profile` via its own `@Resolver(() => ProfileModel)` (see `profile-skills.resolver.ts`);
  the profile module does not know about its extensions.
- Expected failures throw `DomainError` subclasses (`NotFoundError`, `BadInputError`); `format-graphql-error.ts`
  maps them to `extensions.code`.
- `ID` arguments are parsed at the transport boundary with `ParseIdPipe` (`@Args('id', {...}, ParseIdPipe)`);
  services receive `number`.
- GraphQL model classes (`*Model`) are the public contract, extend `BaseModel` (`id`) and declare
  `implements Pick<PrismaModel, 'field' | …>` for exactly the exposed fields — never `implements PrismaModel`
  (it forces internal columns like `avatarKey` into the API).
- **The schema has a cycle** (`Project.experience ↔ Experience.projects`); query depth/aliases/cost are limited by
  validation rules (`graphql/query-limits.ts`, `GRAPHQL_MAX_*`). Adding a bidirectional relation or a growing list:
  re-check limits and update `docs/graphql-query-limits.md`.
- S3: objects meant for browsers live under `public/` (bucket policy grants anonymous read only there), use
  content-addressed keys and are served by a permanent `S3Storage.publicUrl()` with an immutable `Cache-Control`.
  Everything else stays private.
- Every seeded table has a natural unique key the seed upserts by (achievements: `(project_id, sort_order)`), so ids
  exposed by the API stay stable across seed runs. Do not "delete all + recreate" rows that have a public `id`.
- Rate limiting: `GqlThrottlerGuard` (global `APP_GUARD`) counts root GraphQL fields per client IP and answers with
  code `TOO_MANY_REQUESTS` (HTTP stays 200 — `@nestjs/apollo` resets it on purpose). Mark infrastructure endpoints
  with `@SkipThrottle()`. Behind a proxy set `TRUST_PROXY` to the exact number of hops, never `true`.
- Production is a single VPS: `deploy/docker-compose.yml` + Caddy (`deploy/Caddyfile`).
  Only Caddy publishes ports; keep `/health`, Postgres and the S3 API internal.
  Caddy directive gotchas: `rewrite` runs before `uri strip_prefix` (use `handle_path`), and a first argument
  starting with `/` is a matcher (`redir * /target`).
- `src/generated/` is Prisma output: never edit, never commit.
- Schema changes: edit `prisma/schema.prisma` → `npm run db:migrate:dev` → update seed types/data → `schema.gql`
  is regenerated by `start:dev` / `test:e2e` (any env except production); commit it as generated — it is in
  `.prettierignore`, never format it by hand.
- GraphiQL (Nest built-in, `graphiql: GRAPHQL_SANDBOX`) on `GET /graphql` must work in production — there is no
  frontend, it is how the API is tested there. Keep `introspection` on the same flag.

## Conventions

- TypeScript strict + `noUncheckedIndexedAccess`; no `any`.
- Tables/columns snake_case via `@@map`/`@map`; `Int @default(autoincrement())` ids;
  short strings `@db.VarChar(n)`, long prose stays `text`.
- Tests next to the code (`*.spec.ts`); e2e in `test/`.
- Conventional Commits.
